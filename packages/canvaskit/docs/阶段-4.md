当前的 `ShapeBatcher` 实现确实忽略了**层级（z-order / 绘制顺序）**问题，这在设计一个高质量图形引擎时是个致命点。

---

# 🎯 问题说明

在 CanvasKit / Skia 中，**draw 顺序就是视觉层级**。
我们当前的批处理逻辑：

```ts
for (const [, list] of this.groups) {
  for (const { path } of list)
    canvas.drawPath(path, paint);
}
```

→ 按 PaintKey 分组后绘制。
但这会导致：

* **不同层级的 Shape 被乱序绘制**；
* **同色对象可能遮挡错误**；
* **半透明绘制（alpha blending）完全失效**。

---

# ✅ 正确设计：有序合批渲染（Ordered Batching）

我们必须在“性能”和“绘制顺序”之间取得平衡。
这在引擎层面一般通过 **“排序 + 局部批次合并”** 解决。

---

## 🌳 思路概览

1. 每个 `Node` 都有一个 `globalZ`（世界层级）；
2. 渲染器遍历时生成一个**平面渲染队列**；
3. 先按 `globalZ` 排序，再在局部相邻元素中进行合批；
4. 局部相邻、PaintKey 相同的节点可以合并为一个批；
5. 按顺序执行 drawPath，保持视觉一致性。

---

## 🧩 实现步骤

### 1️⃣ 在 Node 中加入层级定义

```ts
// src/scene/Node.ts
export class Node {
  children: Node[] = [];
  parent: Node | null = null;
  zIndex: number = 0; // 局部层级
  globalZ: number = 0; // 世界层级
  visible: boolean = true;

  add(child: Node) {
    child.parent = this;
    this.children.push(child);
    this.sortChildren();
  }

  private sortChildren() {
    this.children.sort((a, b) => a.zIndex - b.zIndex);
  }

  updateGlobalZ(baseZ = 0) {
    this.globalZ = baseZ + this.zIndex;
    for (const child of this.children) {
      child.updateGlobalZ(this.globalZ);
    }
  }
}
```

> 每次场景更新（或渲染前）调用 `root.updateGlobalZ()`，即可得到完整排序。

---

### 2️⃣ Renderer 收集时生成“平面渲染队列”

```ts
// src/renderer/Renderer.ts
private flatList: { path: any; paint: any; z: number }[] = [];

private collect(node: Node) {
  if (!node.visible) return;

  if (node instanceof Shape) {
    const path = node.path ?? node.pathBuilder?.buildIntoPool(node.pathPool);
    const paint = node.paint ?? node.paintPool?.acquire();
    if (path && paint) this.flatList.push({ path, paint, z: node.globalZ });
  }

  for (const child of node.children) this.collect(child);
}
```

---

### 3️⃣ 排序 + 局部合批渲染

修改 Renderer 的 `render()`：

```ts
render(root: Node) {
  const { surface, canvas } = this.context;
  if (!surface || !canvas) return;

  root.updateGlobalZ();
  canvas.clear([1, 1, 1, 1]);
  this.flatList = [];

  // 收集所有 Shape
  this.collect(root);

  // 按 Z 轴排序
  this.flatList.sort((a, b) => a.z - b.z);

  // 按顺序绘制，并在局部范围内合批
  let currentKey: string | null = null;
  let currentPaint: any = null;
  let batchPaths: any[] = [];

  const drawBatch = () => {
    if (!currentPaint || !batchPaths.length) return;
    for (const p of batchPaths) canvas.drawPath(p, currentPaint);
    batchPaths = [];
  };

  for (const { path, paint } of this.flatList) {
    const key = PaintKey.from(paint);
    if (key !== currentKey) {
      drawBatch(); // flush 上一个批次
      currentKey = key;
      currentPaint = paint;
    }
    batchPaths.push(path);
  }

  drawBatch(); // 绘制最后一批
  surface.flush();
}
```

### ✅ 这样有什么好处？

| 问题               | 旧逻辑            | 新逻辑                |
| ---------------- | -------------- | ------------------ |
| 绘制顺序             | 无序（按 PaintKey） | 按 globalZ 排序（正确显示） |
| 合批粒度             | 全局             | 局部（仅相邻相同 Paint 合并） |
| 半透明              | 错误             | 正确                 |
| 性能               | 优化但可能错乱        | 稍减，但结果正确           |
| 复杂场景（1000+Shape） | 乱序混色           | 正确显示 + 稳定性能        |

## 💡 性能建议

| 策略                          | 说明                         |
| --------------------------- | -------------------------- |
| **局部合批 (ordered batching)** | 当前方案，正确且高效                 |
| **同层大批量对象时**                | 可以在 LayerManager 中做更大范围批处理 |
| **Layer 缓存**                | 若整层不动，可缓存为 Surface 离屏绘制    |
| **动态更新 zIndex**             | 只在节点变化时重新排序，避免每帧 sort      |
