# CanvasKit-based 2D 图形库：高性能、高质量分步实现计划


## 一、总体设计原则（必须遵守）

1. **渐进交付**：把大目标拆成小里程碑（每个里程碑能运行、可测试、可替换后端）。
2. **模块化 & 明确边界**：Scene Graph、Renderer、RasterCache、事件系统、资源管理、动画分别独立。接口稳定、实现可替换。
3. **最小可惊喜（Least Surprise）API**：借鉴 Canvas2D/DOM/CanvasKit 的直觉式接口，避免过多魔法。
4. **性能优先级**：避免每帧分配 GC-heavy 对象、使用对象池、批次渲染与脏矩形（dirty-rect）策略。
5. **高质量渲染**：充分利用 Skia 提供的抗锯齿、subpixel text、offline surface（离屏缓存）。
6. **可测试 & 可调试**：提供可视化 debug 模式（显示 bounds、paths、cache hit/miss），并写单元与集成测试。

---

## 二、总体架构（模块关系）

```
Application
  └─ Scene (root Node)
       ├─ Node (transform, style, children)
       ├─ Shape (Path, Fill, Stroke)
       ├─ ImageNode (bitmap, NinePatch)
       └─ TextNode (font, glyph run)

Renderer
  ├─ RenderContext (CanvasKit.Surface, global state)
  ├─ DrawPass (full/partial)
  └─ RasterCache (offscreen surfaces)

EventSystem
  ├─ HitTester (path-based, bounding-box first)
  └─ Pointer/Mouse/Touch dispatcher

ResourceManager
  ├─ TexturePool
  └─ FontManager

Animation / Ticker

Utilities
  ├─ Math / Matrix2D
  └─ Pools / Allocators
```

---

### 阶段 1 — 最小 Scene Graph 骨架（3-5 天）

**目标**：实现 Node、Group、Shape、Renderer，支持 transform、层级渲染

任务清单：

1. 定义基础类型：`Vec2`, `Matrix3`(2D affine), `Rect`, `Color`。
2. Node 基类：`transform`, `visible`, `opacity`, `bounds cache`, `dirty flag`。
3. Shape：持有 CanvasKit.Path（或以命令序列构建 path），支持 `fill` 与 `stroke`（封装 Paint）。
4. Renderer：递归遍历 scene，apply transform，draw path；支持 `canvas.save()` / `canvas.restore()` 与 `canvas.concat()`。
5. 简易示例：画若干矩形与圆，支持子节点的 transform（translate/scale/rotate）。

**性能提示**：

* Node 的 `worldMatrix` 采用脏标记（dirty）惰性计算，避免每帧重复矩阵乘法。
* Path 重复使用，不在每帧重新创建 Path 对象；如果 path 改变再更新。

**交付物**：`demo/scene-graph`（可移动/缩放子节点）

---

### 阶段 2 — Hit Testing 与事件系统（2-4 天）

**目标**：实现基于层次与 shape 路径的命中检测，事件冒泡/捕获

任务与策略：

1. 采用两阶段检测：先矩形包围盒（快速）过滤，再将点变换到本地坐标使用 `Path.contains(x,y)` 或 `op` 判定。
2. 对复杂 path（如带 stroke 的形状）需对点到 stroke 的距离做判断（stroke 模拟或使用 CanvasKit 的 `Stroke` 并判定）。
3. 事件委托：Canvas (DOM) 捕获 pointer 事件后只做一次 root hitTest 并派发。
4. 支持 `stopPropagation` 与 `preventDefault` 概念（逻辑层面）。

**注意**：CanvasKit 不提供 DOM 事件，所有交互都由 JS 逻辑判断并映射到 Node。

**交付物**：`demo/hit-testing`（点击与拖拽 shape）

---

### 阶段 3 — Raster Cache（离屏缓存）与脏矩形（5-8 天）

**目标**：引入离屏缓存以减少重绘成本，支持部分重绘（dirty rect）

核心设计：

* **RasterCache**：对静态或少变的子树创建 `CanvasKit.Surface` 或 `Image` 缓存。

  * key = Node id + transform cache（scale/rotation）
  * LRU 策略 + 最大内存预算（例如 64MB）
* **脏矩形合并**：当节点变动时，记录变动区域，合并后只重绘该区域（支持有限的合成场景）。

实现细节：

1. 提供 API `node.setCache(strategy: 'auto'|'always'|'never')`。
2. 在 render 流程中，如果 node 有有效 cache 且 cache 覆盖当前 transform，则绘制 cache image 而不是遍历子节点。
3. 离屏 surface 的像素比例要跟显示 devicePixelRatio 匹配以保证清晰度。

**性能提示**：

* 不要对频繁动画节点做缓存（例如每帧位置变化）——缓存会失效造成更多开销。
* 离屏表面大小应有上限（比如 2048x2048），超大节点需切片或回退到直接绘制。

**交付物**：`demo/raster-cache`（切换缓存策略并测量 FPS/帧耗时）

## 四、关键实现细节（选取性展开）

### 1. 矩阵与世界变换缓存

```ts
class Matrix2D {
  m: Float32Array; // [a, b, c, d, e, f]
  dirty: boolean;
  multiply(other: Matrix2D) { /* in-place mul */ }
}

class Node {
  localMatrix: Matrix2D;
  worldMatrix: Matrix2D;
  worldDirty: boolean;
  updateWorldMatrix() {
    if (!this.worldDirty) return;
    if (this.parent) {
      this.worldMatrix = Matrix2D.multiply(this.parent.worldMatrix, this.localMatrix);
    } else this.worldMatrix = this.localMatrix.clone();
    this.worldDirty = false;
  }
}
```

要点：避免在渲染循环里盲目递归计算矩阵，采用脏标记并且只在变更时更新。

### 2. Path 对象生命周期

* Path 构造昂贵：应复用 `CanvasKit.Path` 实例
* Node 保存 `pathBuilder`（命令数组）并在变更时（或首次渲染）把命令转换为 `CanvasKit.Path`
* 提供 `Path.equals` 或 `pathVersion` 检测以决定是否重建

### 3. RasterCache 策略示例

* `CacheEntry { image: CanvasKit.Image, bounds: Rect, scaleKey: number, lastUsed: number }`
* `getCache(node, transform)`: 如果 scaleKey 匹配并且 image 可用，绘制 image；否则返回 null

### 4. HitTest 的优化

* 层级遍历从最上层子节点开始（反序），先 bbox，再 path
* 使用简单像素级命中检测仅作为最后方案（读像素昂贵）

## 五、性能优化清单（工程实践）

1. **对象池**：矩阵、点、rect、pathBuilder 都应池化，避免频繁 new。
2. **最小化 JS->WASM 边界调用**：批量操作 CanvasKit API，避免每个小绘制操作跨越边界。
3. **合批渲染**：同样的 paint、相同的 blend/clip，可以合并 draw calls。
4. **避免频繁离屏创建/销毁**：缓存离屏 surface，按需复用。
5. **合理使用 devicePixelRatio**：只在显示分辨率变化或缩放时重烘焙离屏。
6. **剖析工具**：在关键路径插入 timing 信息，统计每帧的 draw calls、cache hit/miss、WASM time。
